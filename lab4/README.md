# Лабораторная работа №4 — вариант 1

## Цель работы

Изучить методы доступа к моноканалу на базе программы лабораторной работы №3:
упрощённый CSMA/CD с эмуляцией занятости канала и коллизий.

Интерфейсы ввода (Input) и вывода (Output), топология, фиксированные параметры
COM-порта и структура кадра сохранены без изменений относительно ЛР3.

## Вариант 1

| Параметр | Значение |
|---|---|
| Вероятность занятости канала | 10 % |
| Вероятность коллизии | 40 % |
| Коллизия | в отношении отдельного байта |
| Дополнение к алгоритму | Jam-сигнал |
| Основа | ЛР3 (циклический код, FCS, bit-stuffing) |

## CSMA/CD (упрощённо, без распараллеливания)

Три ключевых шага в указанной последовательности:

1. **Прослушивание канала** — с вероятностью 10 % канал занят; ожидание слота и повтор.
2. **Обнаружение коллизии** — при передаче каждого байта с вероятностью 40 %.
3. **Случайная задержка** — binary exponential backoff:
   `k = min(n, 10)`, `r ∈ [0, 2^k − 1]`, `delay = r · SLOT_TIME`.

При коллизии передаётся **Jam-сигнал** (`0xEE` × 4 байта), затем backoff и
повторная передача кадра целиком. Приёмник по Jam сбрасывает текущую сборку.

Параметры `SLOT_TIME_MS`, `MAX_ATTEMPTS` и значение Jam пояснены в комментариях
модуля `serial_messenger/backend/csma_cd.py`.

## Интерфейс

- **Error emulation** — как в ЛР3 (ошибки в поле данных).
- **Multiple access** — разрешение/запрет эмуляции множественного доступа.
- **Status** — поля кадра как в ЛР3; отдельно символы `*` по числу коллизий
  при передаче последнего кадра (через пробел).

Окна Input и Output не адаптируются к новым блокам управления.

## Запуск

1. Установите зависимости: `pip install -r requirements.txt`.
2. Запустите `python serial_messenger/main.py`.
3. Выберите COM-порт и скорость (8 / N / 1 фиксированы).
4. При необходимости включите Error emulation и/или Multiple access.
5. Наберите текст: символы копятся до заполнения поля данных, затем уходит кадр.

На обоих концах линии выбирайте одинаковую скорость (пара COM3 ↔ COM4).
