# Лабораторная работа №4 - вариант 1

## Цель работы

Изучить методы доступа к моноканалу на базе программы лабораторной работы №3:
упрощённый CSMA/CD с эмуляцией занятости канала и коллизий.

Интерфейсы Input/Output, топология, параметры COM-порта и структура кадра -
как в ЛР3 (включая эмуляцию ошибки после bit-stuffing).

## Вариант 1

| Параметр | Значение |
|---|---|
| Вероятность занятости канала | 10 % |
| Вероятность коллизии | 40 % |
| Коллизия | в отношении отдельного байта |
| Дополнение к алгоритму | Jam-сигнал (`0xEE` x 4) |
| Основа | ЛР3 |

## Алгоритм CSMA/CD (рассказывать по шагам)

Три шага строго по порядку, без распараллеливания - на передатчике и на приёмнике.

### Передатчик (Multiple access = Enable)

1. **Прослушивание канала** - с вероятностью 10 % канал занят; ждать слот, слушать снова.
2. **Обнаружение коллизии** - кадр уходит **побайтно**. С вероятностью 40 %
   выбирается **один байт** - место коллизии (вариант 1, не кадр целиком).
   Байты до него уходят в линию; на этом байте: коллизия -> **Jam** -> `*` в Collisions.
3. **Розыгрыш случайной задержки** - стандартный BEB:
   `k = min(n, 10)`, `r` из `[0, 2^k - 1]`, `delay = r * SLOT_TIME`, затем повтор кадра.

### Приёмник (Multiple access = Enable)

1. Прослушивание канала (10 %).
2. Обнаружение коллизии по Jam-сигналу - сборка кадра сбрасывается.
3. Розыгрыш задержки BEB.

Параметры `SLOT_TIME_MS`, `MAX_ATTEMPTS`, Jam - в `serial_messenger/backend/csma_cd.py`.

## Интерфейс

- **Error emulation** - как в ЛР3.
- **Multiple access** - вкл/выкл эмуляции множественного доступа.
- **Collisions** - отдельно `*` через пробел по числу коллизий последнего кадра.
- **Status** - три строки кадра как в ЛР3.
- Input и Output не меняются под новые блоки.

## Запуск

1. `pip install -r requirements.txt`
2. `python serial_messenger/main.py`
3. COM3 и COM4, одинаковая скорость (8 / N / 1).
4. При необходимости - Error emulation и/или Multiple access.
